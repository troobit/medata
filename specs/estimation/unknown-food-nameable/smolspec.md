# Unknown Food Nameable

## Overview

The segmenter's `unknown_food` sentinel (palette class 34) marks food it cannot name. Today that region is discarded at four points, so an out-of-palette food refuses with "No food detected" before the review surface ever opens (field session 2026-09-23, `docs/agent-notes/field-truth-sessions.md`: a sesame roll, six single-view and two-view refusals, 1–4 % of each frame labelled unknown and nothing named). This change carries the unknown region through as a volumetric row the user names in review using the existing relabel path, or drops with the existing reject control. Naming is the value: version 1 users will photograph foods the model has not learnt.

## Requirements

1. The system MUST NOT refuse a capture solely because the food the segmenter found is `unknown_food`. `noFoodPixels` is reserved for a frame with no food-like pixels at all; `unrecognisedFood` is no longer thrown (the case stays so persisted outcome rows still decode).
2. The system MUST fit the support plane using unknown pixels as food pixels, on both the single-view and the two-view paths, so the pre-shutter empty-mask gate passes whenever any food-like region exists.
3. The system MUST integrate unknown pixels as their own class in both volume estimators, so the record carries a pre-β volume under the `unknown_food` class id exactly as a named class does.
4. The system MUST emit one row per meal for the unknown class (all unknown regions merge into it, as named classes already do), named "Unknown food", with its measured volume, 0 g carbohydrate, and calibration status `uncalibratedUnity`, and MUST persist it in the record like any other row.
5. In review the unknown row MUST be relabellable from the existing eligible list, and MUST derive its mass and macros from its stored pre-β volume exactly as a named row does (meal-review Req 3, design "Relabel derivation").
6. In review the unknown row MUST be rejectable with the existing reject control (meal-review Req 4), which is how a non-food region is ignored. While unnamed, the row MUST show its volume in cm³ and MUST hide the serving and gram controls, since it has no density to step by.
7. The unknown row's outline on the photo MUST be drawn and selectable like a named row's.
8. Recording with the unknown row still unnamed MUST succeed and MUST keep the existing "unknown region" accessory line (meal-review Req 1.5); the record's total then excludes that row.
9. A recorded meal's unknown row MUST remain relabellable from history through the surfaces that already honour corrections (meal-review Req 8.7).
10. The system MUST absorb sliver classes before volume, on every food-like class alike (named, liquid, or unknown): a food-like class whose total pixel area is under a fraction of the frame's total food-like area is a sliver; each of its connected components is relabelled to the class that dominates its border, excluding other sliver classes, and a component bordered only by sliver classes is left as it is. Background is never a sliver and is a valid absorber. The frame's only food-like class is never a sliver. The fraction starts at 0.10 and MUST be fixed by measurement (see Tests) before the change ships; 0 is passthrough.
11. The system SHOULD keep the shutter disarmed while the live pre-shutter mask has no food-like pixels, showing the existing blocked-shutter chip with the text "No food in view", so a press never arms into a guaranteed refusal.

## Implementation Approach

- **One predicate, not four edits.** Add `ClassPalette.isVolumetricClass(_:)` in `MedataCore/Sources/Segmentation/ClassPalette.swift` = food, liquid, or `unknownFood`. Use it where today's `isFoodClass || isLiquidClass` decides what counts as food-bearing: `App/Pages/Capture/PreShutterSegmenter.swift:297` and `MedataCore/Sources/Pipeline/PipelineBridges.swift:155` (mask builders), `MedataCore/Sources/Pipeline/FoodRegionCoverage.swift` (`foodCoverageFraction`), `MedataCore/Sources/Volume/HeightFieldEstimator.swift:115`, `MedataCore/Sources/Volume/VoxelCarveEstimator.swift:178,312` and `MedataCore/Sources/Volume/MaskMatcher.swift:47`. `isFoodClass` keeps its solid-only meaning for occlusion and coverage-refusal rules, which stay unchanged.
- **Sliver absorption (Req 10).** Second rule in `regulariseLabelMap` (`MedataCore/Sources/Segmentation/PostProcessing.swift:256`), which already discovers every 4-connected component and its dominant bordering class. Before the scan, histogram the labels once; the sliver set is every food-like class (new `isVolumetricClass`) whose count is under `sliverFraction` times the food-like total. During the scan a component of a sliver class is reassigned to its dominant bordering non-sliver class read from the original labels, ties to the lowest id, as the speckle rule does. Per class, not per component, because food sits in clumps: thirty separate peas are one large class and keep their row, while a 2 % `cheese` fringe on a 10 % unknown region (the sliver bugfix's case) is one small class and joins whatever it borders. Absorbing into background drops volume that is, by construction, under the fraction of the plate. Deterministic, single extra histogram, `sliverFraction: 0` is byte-identical passthrough. Applies to each view independently on the two-view path.
- **Gates.** Delete `enforceRecognisedFoodDominance`, its two constants, and its call at `Pipeline.swift:352`. Keep `EstimationFailure.unrecognisedFood` and its copy for decoding history; nothing throws it. `enforceMinimumFoodCoverage` counts unknown through the new predicate. `InterClassOcclusionDetector` stays solid-only, so occlusion between an unknown region and a named one is not detected; accepted.
- **Row synthesis.** `Macros.compute` (`MedataCore/Sources/Macros/Macros.swift:110`) skips classes with no database row. Add one branch: when `classId == "unknown_food"`, emit a `PerClassMacros` with the volume, mass 0, all macros 0, `betaUsed 1`, status `uncalibratedUnity`, sources `"unknown"`. No database row is added.
- **Review.** `App/Pages/MealReview/MealReviewModel.swift:151` builds rows from `record.macros.perClass`; the unknown row arrives for free. One conditional in the row view hides the amount controls and shows cm³ while `classId == "unknown_food"` (Req 6). Display name "Unknown food" comes from `MedataFormat.prettify` on the class id, the shared row-naming path (`MealReviewModel.swift:864`). Relabel (`:375`) and reject need no change if the row is ordinary; the eligible list excludes `unknown_food` itself. The accessory line (Req 1.5) already reads `presentClassIds`.
- **Shutter.** `CaptureFlowModel.hasUsablePreShutterMask` (`App/Pages/Capture/CaptureFlowModel.swift:230`) additionally requires the latest mask to have at least one 1-bit; `PreShutterSegmenter` publishes that count alongside the mask.
- **Tests and measurement.** MedataCore unit tests: a small named component bordering a larger unknown one is absorbed; a small unknown fringe on rice joins rice; a class that is large in total but split into many small components is kept; two adjacent sliver classes bordered by nothing else are left unchanged; fraction 0 is byte-identical passthrough. Measurement, run through `HarnessCLI seg-bench` and `make harness-accuracy` over `tmp/n5k_fixtures` (3,485 Nutrition5k fixtures with truth masks and carbs) at fractions 0, 0.05, and 0.10: mean food-class IoU must not fall, and carb mean absolute error must not rise, against fraction 0. The fraction that ships is the largest of the three that meets both; the numbers go in the decision log. The five device bundles under `tmp/device_captures` are replayed the same way as a spot check. Remaining unit tests: coverage fraction and minimum-coverage gate with an all-unknown argmax
- **Dependencies.** meal-review relabel derivation (`specs/ui/meal-review/design.md`, "Relabel derivation"); serving-adjust row controls; capture-bundle recorder unchanged.
- **Out of scope.** Free-text naming and adding foods to the database (the correction record's class id is a plain string, so a later database-added class needs no schema change here); model retraining for the sesame roll (`myfoodrepo-bridge`); ranked alternatives for unknown rows (`alternative-class-candidates`); any change to the refusal overlay layout.

## Risks and Assumptions

- Risk: a napkin, hand, or shadow labelled unknown becomes a row instead of a refusal | Mitigation: reject is one tap and reversible (Req 4.3); the recorded total excludes an unnamed row.
- Risk: a genuinely small food is absorbed. At fraction 0.10 a side under a tenth of the plate's food area joins its neighbour or the background, and its carbs go with it | Mitigation: by construction the loss is bounded by the fraction of the plate, and the N5k carb-error measurement is the gate; if it rises, the fraction drops.
- Risk: the sliver case (bugfix `unrecognised-food-estimated-as-residual-sliver`, a 0.21 % `cheese` fringe on a 10 % unknown region) would return as a confident named row once the dominance refusal is gone | Mitigation: at 2 % of the food-like area that fringe is a sliver under Req 10 and is absorbed before volume.
- Risk: an unknown row recorded unnamed reads as "0 g" in Records and the Graph | Mitigation: the Req 1.5 accessory line stays on the record, and Req 9 keeps it relabellable from history.
- Risk: density-free mass. The unknown row has volume but no mass until named | Mitigation: the row shows cm³ until relabelled; serving controls are disabled on it.
- Assumption: `SegBench.sample` and `FixtureRunner` run the post-processor's regularisation on the stored probabilities, so the measurement exercises the new rule; verify in the measurement task and, if not, route both through it.
- Assumption: the β application step tolerates a class with no `BetaCorrection` entry by using unity and `uncalibratedUnity` (pipeline Req 8.6 says so; verify in the volume task before relying on it).
- Assumption: `perClassVolumesPreBetaCm3` is keyed by class id string and `unknown_food` round-trips through `MealRecord.proto` without schema change (class ids are strings, `FoodEntry.proto:9`).
- Assumption: two-view path refuses at the same fitter gate (confirmed 2026-09-23 log: `capturePath=two_view_sfs … failure=emptyFoodMask`), so Req 2 covers both.
- Prerequisite: a Release build with the real segmenter; the Debug stub never emits class 34.
