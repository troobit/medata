- [x] 2. Implement `PixelBufferAdapter` (green) <!-- id:pba-impl -->
  - **Outcome:** A new file `MedataCore/Sources/CaptureKit/PixelBufferAdapter.swift` exposes the public enum, `ConversionError`, `Output`, and `static func convert(_:) throws -> Output` per `design.md`'s Components and Interfaces. All nine tests from task 1 pass. The file is not wrapped in `#if canImport(ARKit) && os(iOS)` so it builds on iOS Simulator and macOS too ([Req 3.2](requirements.md#3.2)).
  - **Approach:** vImage backend per [Decision 5](decision_log.md). Cache `vImage_YpCbCrToARGB` info struct as `nonisolated(unsafe) static let`, built once with `vImageConvert_YpCbCrToARGB_GenerateConversion(...)` using `kvImage_YpCbCrToARGBMatrix_ITU_R_601_4` and a full-range `vImage_YpCbCrPixelRange` (Yp 0..255, Cb/Cr 0..255, zero offset 128). For YCbCr biplanar full-range: call `vImageConvert_420Yp8_CbCr8ToARGB8888` with `permuteMap: [3, 2, 1, 0]` to land bytes in B/G/R/A order; allocate destination at row stride exactly `width * 4` ([Req 1.3](requirements.md#1.3)). For `kCVPixelFormatType_32BGRA` / `_32RGBA`: lock buffer `.readOnly`, copy bytes into an owned contiguous `Data` (collapsing any per-row stride padding), unlock; tag the output `.bgra8` or `.rgba8`. For unsupported four-CCs: throw `ConversionError.unsupportedSourceFormat(fourCC: …)` rendering the OSType as four ASCII characters. On any `kvImage…` failure: throw `ConversionError.conversionFailed(vImageErrorCode: Int(err))`. Use `defer { CVPixelBufferUnlockBaseAddress(buffer, .readOnly) }` on every path so the source buffer is released on errors too. Allocate at most one transient destination buffer to honour [Req 4.2](requirements.md#4.2).
  - **Verification:** `swift test --filter PixelBufferAdapterTests` is green. `swift build` and `swift build -c release` are clean (no new warnings). `grep -rn "PixelBufferAdapter" MedataCore/Sources` shows the new file as the sole production-source reference until task 4 lands.
  - **References:** requirements.md ([1.1](requirements.md#1.1)–[1.5](requirements.md#1.5), [2.1](requirements.md#2.1)–[2.4](requirements.md#2.4), [3.1](requirements.md#3.1), [4.2](requirements.md#4.2), [4.3](requirements.md#4.3)), design.md (Architecture, Components and Interfaces, Error Handling), decision_log.md (Decisions 1, 3, 5, 6).
